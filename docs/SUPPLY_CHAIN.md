# Supply-chain checks

The repository pins dependencies and commits `bun.lock`; install locally with `bun install --frozen-lockfile`. Dependabot proposes Bun dependency updates weekly, and [`.github/workflows/ci.yml`](../.github/workflows/ci.yml) runs build and test checks on pull requests, not automated dependency vulnerability audits. These measures do not establish that packages are safe or guarantee that GitHub's optional security features are enabled.

Run `bun audit --audit-level=low` (or `--audit-level=high`) using the pinned Bun version to consult the registry's known advisory data. An audit can fail because of vulnerabilities or a registry/network problem; inspect the output and do not treat a scanner error as a clean result. A clean result only covers known advisories reported by the registry at that time. Review applicability, exploitability, direct and transitive impact, and fixed versions before changing dependencies. Record a risk acceptance and an expiry for any justified exception; do not suppress advisories to make a check green.

Secret scanning is not configured inside this repository's workflow files (external checks such as GitGuardian or GitHub secret scanning depend on repository settings and plan). Evaluate GitHub secret scanning and push protection for the repository's actual visibility and plan, or an independently reviewed scanner; neither should print detected secret values into logs or artifacts. Test with vendor-provided synthetic fixtures and investigate false positives without publishing real credentials. If a real secret is exposed, restrict access, revoke or rotate it, and follow the incident process; deleting a line or rewriting history alone does not revoke it.

The audit is not a blocking check: registry availability, advisory changes, and failure behavior need a deliberate operational decision. Scanners, configuration, and dependency upgrades require high-risk review. Never execute untrusted pull-request code with privileged CI permissions.
